1. У чому полягає різниця між модулем та пакетом у Python? Яку роль у структурі пакета відіграє файл __init__.py? -
У Python модуль — це будь-який окремий файл із розширенням .py, який містить логічно завершений код (змінні, функції, класи).
Пакет же є формою організації, що являє собою директорію, яка об'єднує кілька модулів або навіть підпакетів. Файл __init__.py виконує роль ініціалізатора: він вказує інтерпретатору, що дана папка є пакетом.
Окрім маркування, цей файл дозволяє керувати експортом (наприклад, через список __all__) або виконувати попереднє налаштування пакету при його імпорті, що робить структуру проєкту більш модульною та ієрархічною.


2. Навіщо у професійній розробці використовуються віртуальні оточення (venv)? Яку проблему вирішує фіксація залежностей у файлі requirements.txt? -
Віртуальні оточення (venv) використовуються для ізоляції середовища виконання конкретного проєкту від системного Python та інших проєктів.
Це запобігає «конфліктам версій», коли два різні застосунки потребують різних версій однієї бібліотеки.
Файл requirements.txt вирішує проблему відтворюваності: фіксуючи точні версії залежностей, розробник гарантує, що код, який працює на його машині, працюватиме ідентично на сервері або комп'ютері колеги.
Це усуває ситуацію «у мене все працює», роблячи процес розгортання передбачуваним.



3. Поясніть різницю між абсолютним та відносним імпортом. Чому в «точці входу» проєкту (main.py) рекомендується використовувати лише абсолютні імпорти?
Абсолютний імпорт визначає повний шлях до модуля від кореня проєкту (наприклад, import myproject.utils), тоді як відносний використовує крапкову нотацію для вказівки на поточну або батьківську директорію (from . import config).
У «точці входу» (наприклад, main.py) рекомендується використовувати лише абсолютні імпорти, оскільки під час запуску файлу як основного скрипта інтерпретатор вважає його модулем __main__.
У такому стані Python не знає про місце розташування файлу в ієрархії пакетів, що призводить до помилки ImportError при спробі використати відносний шлях.


4. У чому перевага використання бібліотеки pathlib перед модулем os.path при роботі зі шляхами до файлів?
Бібліотека pathlib пропонує об'єктно-орієнтований підхід до роботи зі шляхами, тоді як os.path працює суто з рядками.
Використання об'єктів Path робить код більш читабельним і лаконічним: наприклад, з'єднання шляхів через оператор / (path / "subdir" / "file.txt") є набагато інтуїтивнішим, ніж багаторазові виклики os.path.join().
Крім того, pathlib автоматично враховує особливості різних операційних систем (роздільники в Windows та Unix), надаючи при цьому зручні методи для перевірки існування файлів, створення папок або читання контенту без явного відкриття контекстного менеджера.

5. Порівняйте формати JSON та Pickle. У яких ситуаціях текстова серіалізація (JSON) є кращою за бінарну (Pickle) і навпаки?
JSON - це текстовий, людиночитаний формат, який є стандартним для обміну даними між різними мовами програмування.
Його варто обирати для веб-API та конфігураційних файлів через безпеку та кросплатформеність.
Pickle - це специфічний для Python бінарний формат, який дозволяє серіалізувати складні об'єкти (класи, екземпляри, функції), що не підтримуються JSON.
Проте Pickle є небезпечним (може виконати довільний код при десеріалізації) і не може бути прочитаний іншими мовами, тому його використовують лише для тимчасового збереження стану об'єктів у межах Python-інфраструктури.



6. Чому при відкритті текстових файлів для читання або запису критично важливо явно вказувати параметр encoding="utf-8"?
Явне вказання encoding="utf-8" є критично важливим, оскільки різні операційні системи використовують різні кодування за замовчуванням (наприклад, Windows часто використовує cp1251 або cp1252).
Якщо файл був створений в одному кодуванні, а зчитується в іншому, виникнуть помилки декодування або «биті» символи.
UTF-8 є міжнародним стандартом, що підтримує символи більшості мов світу, і його використання гарантує стабільну роботу програми незалежно від мовних налаштувань ОС користувача.



7. Що таке «ротація логів» і чому вона є обов'язковою для систем, які працюють у режимі 24/7?
Ротація логів - це процес автоматичного архівування або видалення старих файлів журналів (логів) при досягненні певного розміру або терміну давності.
Для систем, що працюють безперервно, це обов’язково, оскільки без ротації файл логів може розростися до гігантських розмірів, заповнивши весь вільний простір на диску.
Це призведе до відмови всієї системи. Ротація дозволяє зберігати лише актуальну інформацію за певний період (наприклад, останні 7 днів), підтримуючи стабільність сервера.


8. Навіщо потрібен файл .gitignore і які типи файлів (із створених у межах цієї лабораторної роботи) за жодних обставин не повинні потрапляти у віддалений репозиторій?
Файл .gitignore використовується для того, щоб Git ігнорував технічні або конфіденційні файли, які не мають бути частиною історії версій.
У межах лабораторної роботи до репозиторію категорично не повинні потрапляти:
Папка віртуального оточення (venv/, .env/) — вона містить сотні мегабайт сторонніх бібліотек, які мають встановлюватися окремо через requirements.txt.
Тимчасові файли кешу (__pycache__/, .pyc) — вони специфічні для конкретного запуску.
Локальні бази даних (наприклад, db.sqlite3), якщо вони містять реальні дані.
Конфіденційні дані (ключі API, паролі), які можуть бути у файлах конфігурації.
